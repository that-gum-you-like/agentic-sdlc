# Design: runtime-state-isolation

**Date**: 2026-11-12
**Author**: Claude with Bryce
**Status**: design

---

## Context

### Current State

- Scheduler units (`sdlc-sched-*`, generated by `agents/scheduler-install.mjs` from `agents/cron-schedule.json`) run `node ~/agentic-sdlc/agents/...` in the human checkout.
- `config.agentsDir` (`agents/load-config.mjs`) resolves to the project's `agents/`; `memory-manager.mjs` reads/writes `agents/<agent>/memory/<layer>.json` there; `version-snapshot.mjs` snapshots to tracked `agents/versions/<date>/`.
- The drain worker runs in `~/.sdlc-drain-clone-<project>`, hard-reset to `origin/<base>` before each pass; `drain-trespass-guard.sh` watches the human checkouts.
- `queue-drainer.mjs archive` renames finished task files from tracked `tasks/queue/` to untracked `tasks/completed/`.
- `sdlc-update.service` is `git pull --ff-only` with no preconditions, installed by hand outside the repo.

### Problem Restatement

Runtime state is written inside a human-owned working tree, so the tree is always dirty and the tools that protect or update it either fail silently or revert real work.

---

## Goals

- After any scheduler run, the live checkout has zero changes attributable to the framework (verifiable by `git status --porcelain`).
- Agent memory written by any process (timer, drain worker, reviewer, interactive session) survives every `reset --hard`/`clean` and is never lost in migration.
- Memory the agents "know" stays reviewable by a human through a batched PR, not a silent disk file.
- `sdlc-update` pulls when it safely can and otherwise alerts once with the specific cause.
- Root-owned or otherwise foreign-owned paths in the live checkout are detected and reported within one scheduler tick; the drain never runs as root.
- One environment variable (`SDLC_STATE_DIR` unset to legacy mode) rolls the whole thing back.

## Non-Goals

- No new required configuration. Everything defaults (state dir, thresholds); nothing the operator must fill in (feedback: no gratuitous required fields).
- No automatic stash, reset, `chown`, `sudo`, or deletion in a human checkout. Tools report and print the command a human can run.
- No sync of state between hosts.
- No change to drain model selection, mutex, or PR caps.
- No change to `pm/` (already ignored) or to how `agents/versions/` is laid out.

---

## Design

### Overview

Three storage classes, one rule each:

| Class | Examples | Lives in | Written by | Reaches git by |
|---|---|---|---|---|
| Code, specs, config | `agents/*.mjs`, `openspec/`, `budget.json`, `AGENT.md`, `tasks/queue/*.json` | git | humans and reviewed PRs | PR |
| Curated seed | `agents/<agent>/memory/*.json`, `agents/versions/` | git (frozen) | `memory-publish` only | batched PR from a worktree |
| Runtime state | live memory layers, `vectors.json`, audit log, error signatures | `$SDLC_STATE_DIR` | everything at runtime | never (publish exports a scrubbed copy) |

`stateDir` default: `${XDG_STATE_HOME:-~/.local/state}/sdlc/<project-name>/`. This is the same tree as `~/.local/state/sdlc/telegram-sent.jsonl`, so operators already know where to look. It is per project, so
`~/tally` and `~/nels-workshop` get their own memory without sharing.

### Components

#### State directory resolver

**File(s)**: `agents/load-config.mjs` (modify), `agents/state-dir.mjs` (new, ~60 lines, pure helpers exported)

`config.stateDir` is `process.env.SDLC_STATE_DIR` if set, else the default above. `memoryDir(agent)` = `<stateDir>/memory/<agent>/`; `memoryPath(agent, layer)` is the single place that knows. The directory is created lazily with
mode `0700` by the current user; creation is refused if the target exists and is not owned by the current uid (so a root-created state dir cannot silently become the sink). Legacy mode: `SDLC_STATE_DIR=legacy` makes
`memoryDir` return `agents/<agent>/memory/` exactly as today. That is the rollback.

#### Memory read/write through the resolver

**File(s)**: `agents/memory-manager.mjs`, `agents/version-snapshot.mjs`, `agents/rem-sleep.mjs`, `agents/worker.mjs`, `agents/pr-auto-review.mjs` (recall call at `:161`), `agents/rag-indexer.mjs`

`getMemoryPath` delegates to `memoryPath`. Read order: state file, else the tracked seed (read-only fallback), else empty. First write copies the seed layer into state (so a layer is never created from nothing when a seed exists),
then writes atomically (temp file in the same directory, `fsync`, `rename`). `saveMemory`'s audit append moves from `pm/memory-audit.jsonl` to the same line format in `<stateDir>/memory-audit.jsonl` while keeping the
`pm/` path as a symlink-free fallback if the state dir is unwritable; the existing "audit failure never fails the save" invariant stays. `version-snapshot snapshot` reads live memory from state and still writes to tracked
`agents/versions/<date>/memory/<agent>/`; `restore --memory` writes to state, not to the seed.

Concurrency: the weekly REM timer and a drain worker can both call `saveMemory`. Atomic rename gives last-writer-wins per layer file, which is the existing behaviour; per-agent advisory lock (`<stateDir>/memory/<agent>/.lock`, `mkdir` atomic, stale after 10 min, same idiom as the drain mutex) serialises
read-modify-write so two writers cannot interleave a layer. A held lock past a 5 s wait degrades to "skip the write, log, exit non-fatally" for timers and "retry" for workers.

Drain worker wiring: `hermes-drain.sh` already pins `SDLC_PROJECT_DIR` to the clone. It additionally exports `SDLC_STATE_DIR` (the host's, unchanged) so a worker in the clone writes into the host state dir rather than into the clone
that the next pass erases. This is what closes the root gap.

#### Seeds and `memory-publish`

**File(s)**: `agents/memory-publish.mjs` (new), tracked `agents/<agent>/memory/*.json` (become seeds)

`memory-publish` is the only writer of seeds. It: (1) creates a scratch worktree off `origin/<base>` through `agents/worktree.mjs` conventions (branch `chore/memory-publish-<date>`), (2) for each agent and layer computes the
diff between state and seed, (3) runs `pii-scrub.mjs` and a secrets-pattern check on the *added* content and refuses the whole publish if anything matches (nothing is written; the finding is alerted once), (4) writes the changed
layers into the worktree, (5) commits, pushes, opens a PR, and never merges. If there is no diff it exits 0 and creates nothing. It runs weekly (new schedule `memory-publish-weekly`, Sun 23:45, after REM sleep at 23:00) and on demand.
`pr-auto-review` treats `agents/*/memory/**` as ordinary reviewable content (it is not on the guardrail surface today); the PR title prefix `chore(memory):` makes them easy to batch-approve.

#### Task archive abolition

**File(s)**: `agents/queue-drainer.mjs`, `agents/adapters/orchestration/file-based.mjs`, `agents/load-config.mjs`, `agents/capability-monitor.mjs`, `agents/migrate-task-archive.mjs` (new, one-shot)

`archiveTask` stops moving files: it sets `archived_at` (ISO) on the task JSON in `tasks/queue/` and keeps `status: completed`. `loadCompletedCount` counts queue files with `archived_at`; `capability-monitor`
reads archived tasks from the queue instead of `completedDir`. `config.completedDir` is kept (still resolves) but no code writes to it; a legacy `tasks/completed/` that exists is read for counts only, so old data is not hidden. The task
list view hides `archived_at` tasks by default (`--all` shows them). The one-shot migration restores any file in `tasks/completed/` into `tasks/queue/` when the same name is absent, and when present with different content keeps the
queue version and writes the other to `<stateDir>/migration/task-archive-conflicts/` (2 of 146 differ today). It never deletes `tasks/completed/`; it prints the `sudo`-free instruction for a human to remove it (`chown` is needed for the root-owned dir; reported, not run).

#### Guarded `sdlc-update`

**File(s)**: `agents/sdlc-update.mjs` (new), `agents/templates/systemd/sdlc-update.service.template` (new, repo-owned copy of the unit), `agents/scheduler-install.mjs` (document, not manage)

Algorithm, all `git -C <repo>` with the repo derived from the script location:

1. `git fetch --quiet origin` (failure -> alert `fetch-failed`, exit 0; the next tick retries).
2. Compute `behind`, `ahead`, `dirty` = tracked changes (`diff --name-only HEAD`), `untracked` (not ignored), `branch`, `foreign` (paths not owned by the current uid, via `checkout-doctor` helper).
3. If `branch != main`, or `ahead > 0`, or the working tree is mid-merge/rebase: no pull, alert `not-on-main`/`diverged`.
4. If `dirty` is non-empty: intersect it with `git diff --name-only HEAD..origin/<base>`. Empty intersection -> `git merge --ff-only` is safe and runs (git permits it); non-empty -> no pull, alert `dirty-overlap` listing the colliding paths (max 10).
5. Otherwise `git merge --ff-only origin/<base>`.
6. Drift alert: if `behind > 5` after the attempt and no pull occurred, alert `drift` with the count and the oldest unpulled commit date. Never louder than once per cause per 24 h.

Alerts go through `triggerNotificationOnce('sdlc-update:<cause>', 'highSeverityFailure', msg)` (`agents/notify.mjs:777`), so they inherit the existing dedupe window. Success with a pull is silent (heartbeat reports drift trend);
this matches the channel policy in `hermes-drain.sh` ("success is deliberately silent"). Exit code is always 0 unless the script itself crashes, because a non-zero exit is the current failure that nobody reads.
**Never** stash, reset, checkout, clean or chown in this script.

The unit file lives in `~/.config/systemd/user/` and installing the new `ExecStart` is a Bryce-only step (task RS-013); the repo ships the template and a test asserts the template calls `sdlc-update.mjs`.

#### Checkout doctor and no-root rule

**File(s)**: `agents/checkout-doctor.mjs` (new), `agents/hermes-drain.sh`, `agents/drain-supervisor.mjs`, `agents/health-check.mjs`

`checkout-doctor [--json] [--repo <path>]` reports: root/foreign-owned paths (`find -not -user`, skipping `.git/objects` internals unless owned wrongly), untracked non-ignored paths, tracked modifications, branch, ahead/behind, and whether the state
dir is owned correctly. It is read-only and prints, for each foreign path, the exact command a human can run (`sudo chown -R bryce:bryce <path>`). `health-check.mjs` calls it and raises the existing non-ok notification path.
`hermes-drain.sh` and `drain-supervisor.mjs` exit immediately with rc 98 and a one-line message when `id -u` is 0 (the drain has no legitimate reason to be root: the user units already run as the user), notifying once.
`agents/secrets.mjs` (root, unreadable, untracked) is reported by name as the standing example, not touched.

#### Guard and review interaction

**File(s)**: `agents/drain-trespass-guard.sh` (comment + one assertion), `tests/drain-trespass-guard.test.mjs`, `agents/pr-auto-review.mjs` (recall via resolver only)

With memory in the state dir and archive in place, the scheduler jobs no longer write tracked files in the live checkout, so the guard's restore-and-save-patch behaviour becomes correct by construction: any modified tracked file
after a drain is a trespass, or a human editing mid-drain (already exempted via the pre-run `guard_dirty` snapshot, unchanged). The guard's behaviour is not loosened. The false-positive source is removed instead. The header comment is updated to say
so, and a regression test simulates a REM-sleep write under the new resolver and asserts the live tree stays clean. `pr-auto-review.mjs` calls `memory-manager.mjs recall` with `SDLC_PROJECT_DIR=repoDir`; because
`SDLC_STATE_DIR` is inherited from the environment, a review in a clone reads the host's real memory instead of the clone's stale seed (an improvement; before, the reviewer recalled whatever that PR's snapshot contained).

### Data Flow

```
timer / worker / reviewer
   └─ memory-manager.saveMemory(agent, layer)
        └─ state-dir.memoryPath()  ->  $SDLC_STATE_DIR/memory/<agent>/<layer>.json   (atomic, locked)
                                               │
                    weekly memory-publish ─────┘  (scrub, diff, refuse on secrets)
                         └─ scratch worktree off origin/main -> branch chore/memory-publish-<date> -> PR (never self-merged)
                                   └─ human review -> merged seed in agents/<agent>/memory/

sdlc-update (daily): fetch -> classify tree -> ff-only if safe | alert once with cause
checkout-doctor (health-check, on demand): foreign owners, strays, drift
```

## Decisions

### Decision 1: Runtime memory lives outside git; the tracked files become frozen seeds

**Chosen**: state dir + seeds + batched publish PR.

**Considered**: gitignore in place (loses history/review and does not survive clone resets); per-write PRs (floods review, conflict-prone); run timers in worktrees (large change to every scheduled script).

**Rationale**: memory has one write path, so relocation is cheap; seeds keep the human-visible history and give a fresh clone a starting point; publish gives review without making every REM pass a PR. It fixes dirt and loss together.

### Decision 2: Abolish `tasks/completed/` rather than track or ignore it

**Chosen**: `archived_at` stamp in place; queue is the single source of truth.

**Considered**: track it (duplicates 144 files), ignore it (archive keeps deleting tracked files).

**Rationale**: upstream already keeps finished tasks in the queue with `status: completed`. The archive step existed to keep a directory listing short; a stamp and a default filter does that without moving files.

### Decision 3: `sdlc-update` alerts; it never stashes

**Chosen**: classify, pull only when git itself would succeed, otherwise one deduped alert naming the cause and the colliding paths.

**Considered**: labelled stash-then-pull (proposed in the brief); fail loudly via systemd `OnFailure`.

**Rationale**: a stash in a human checkout hides work and is exactly what the standing rule forbids; a labelled stash is still a surprise to whoever opens `git stash list` next week. With runtime state moved out, the dirty cases that remain are the human's own, and the human is the right person to resolve them. The "safe subset" rule (dirty files not in the incoming diff still fast-forward) keeps the common case working with no alert at all. If Bryce prefers the labelled stash, it is a single branch in `classifyTree` (open question 3).

### Decision 4: Refuse to drain as root and report foreign ownership; do not repair it

**Chosen**: no-root exit (rc 98) + read-only `checkout-doctor`.

**Considered**: auto-`chown` via sudo (no: needs privilege and hides the cause); ignore root files (they already broke `git clean` and left an unreadable module).

**Rationale**: the user units already run unprivileged, so a root-owned write means a second path (container bind-mount, a manual `sudo`) that must be found and closed, not papered over. Origin is unestablished (open question 1), so the design makes the symptom visible and blocks the one place the framework controls.

### Decision 5: Do not loosen the trespass guard

**Chosen**: remove the false-positive writers instead.

**Considered**: an allowlist of "known timer paths" the guard ignores.

**Rationale**: an allowlist makes the guard blind to exactly the files a worker would most plausibly corrupt (memory, queue). Moving the writers out leaves the guard strict and correct.

## Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Migration loses or forks memory | Medium | High | `migrate-runtime-state.mjs` copies seed -> state, verifies sha256 of every layer, writes a manifest, refuses to flip if any mismatch; seeds are never deleted; a pre-migration `version-snapshot` is taken; PR #164's preserved lesson is asserted present after migration. |
| State dir not backed up | Medium | Medium | `memory-publish` weekly PR is the backup; `version-snapshot` already snapshots; state dir documented in RUNBOOK. Disk loss costs at most one week of memory. |
| Two processes interleave a layer write | Low | Medium | Per-agent mkdir lock + atomic rename; tested with two concurrent writers. |
| Published memory leaks a secret/PII to a public PR | Low | High | `pii-scrub` + secrets patterns on added content; refuse whole publish on a hit; PRs are private-repo reviewed, never self-merged. |
| `memory-publish` PRs pile up unreviewed | Medium | Low | One open publish PR at a time (skip if one is open); `pr-auto-review` list-flagged surfaces it. |
| Other projects' agents (`~/tally` etc.) break when memory moves | Low | Medium | Project-keyed state dir; legacy mode per process via `SDLC_STATE_DIR=legacy`; migration script is per project and idempotent. |
| `sdlc-update` alert fatigue | Low | Low | `triggerNotificationOnce` window (24 h) per cause; success silent. |
| Touching guardrail-surface files (`hermes-drain.sh`, guard, `pr-auto-review.mjs`) via the cheap drain | High if seeded | High | Those tasks carry `Lane: interactive` (curriculum-v2 seeder convention, CV-006); the new files are hermes-lane safe. |
| `tasks/completed/` removal blocked by root ownership | Certain | Low | Migration never deletes it; prints the one command for a human. |

## Testing Approach

- **Unit tests**: `tests/state-dir.test.mjs` (resolver, legacy mode, foreign-owner refusal); `agents/__tests__/memory-state.test.mjs` (read order, seed fallback, atomic write, lock, audit never fails the save, snapshot/restore through state); `tests/sdlc-update.test.mjs` (`classifyTree` table: clean+behind, dirty-no-overlap, dirty-overlap, ahead, wrong-branch, fetch-fail; alert dedupe; never calls stash/reset); `tests/checkout-doctor.test.mjs` (fixture repo with a file `chown`-simulated via an injectable stat; json output); `tests/memory-publish.test.mjs` (no diff = no PR; secret in diff = refusal and no write; diff = branch+PR with injected `gh`).
- **Integration tests**: `tests/runtime-state-isolation.test.mjs` runs a throwaway repo through archive + REM-sleep + snapshot with `SDLC_STATE_DIR` set and asserts `git status --porcelain` is empty; extends `tests/drain-trespass-guard.test.mjs` with the timer-writer case; extends `tests/hermes-drain.test.mjs` (state dir exported to worker, rc 98 as root via injectable uid).
- **Manual verification**: after rollout, one scheduler week; `checkout-doctor --json` shows zero findings; the open PR #164 lesson is present in `<stateDir>/memory/sdlc-developer/long-term.json`; `systemctl --user start sdlc-update` on a deliberately dirty-overlap tree yields exactly one alert.
